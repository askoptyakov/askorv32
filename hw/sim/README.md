Тесты ядра (RV32IM, CSR, прерывания, отладчик)
==============================================

Самопроверяющиеся программы на ассемблере прогоняются в Icarus Verilog на всей системе `top.sv`: ядро, память BSRAM (модель SP из библиотеки GOWIN), `memmux`, CLINT, PLIC, таймер STIM, GPIO, модуль отладки. Проверяются однотактное и конвейерное ядро.
- **RV32IM:** 45 программ, по одной на инструкцию, 1835 тестов (из них расширение M — 8 программ по 64 теста). Программы собираются с `-march=rv32im_zicsr`.
- **Привилегированная часть** (`tests/priv/`): CSR-инструкции (36 проверок), исключения и `mret` (63), прерывания (32), PLIC (21), отладчик (`dbg`: сценарий OpenOCD по JTAG и 2 проверки в программе).

#### Запуск
```
py hw/sim/run_tests.py                        # все инструкции, оба ядра
py hw/sim/run_tests.py add lw beq             # выбранные инструкции
py hw/sim/run_tests.py --core pipeline        # одно ядро: single | pipeline
py hw/sim/run_tests.py jalr --core single --vcd   # + диаграммы hw/sim/build/jalr_single.vcd для GTKWave
py hw/sim/run_tests.py --gen                  # перегенерировать tests/rv32i/*.S
py hw/sim/run_tests.py --imem-kb 32 --text-base 0x1f00   # IMEM 32 кБайт, код на границе кластеров BSRAM
py hw/sim/run_tests.py csr trap irq plic dbg  # только привилегированная часть
py hw/sim/run_tests.py --rf-garbage          # x1..x31 при старте - мусор (на плате регистры не сбрасываются)
```
Нужны Icarus Verilog, xPack RISC-V GCC и GOWIN EDA (из неё берётся `prim_sim.v`), см. [sdk/SETUP.md](../../sdk/SETUP.md).

При ошибке выводится инструкция, номер и имя теста, полученное и ожидаемое значение:
```
jalr   [pipeline] тест 14: jalr[target&~1,rs1+1,imm=0]  получено 0x00000375, ожидалось 0x00000374
```
По номеру теста его можно найти в `tests/rv32i/<инструкция>.S`: `TEST_...(14, ...)`.

#### Что проверяется
| Группа | Проверки |
|--------|----------|
| Значения | граничные случаи: 0, ±1, 0x7FFFFFFF, 0x80000000; для сдвигов — только 5 младших бит `rs2`; для типа I — бит 30 инструкции не путает `addi` с `sub` |
| Регистры | `rd=rs1`, `rd=rs2`, чтение `x0`, запись в `x0` не выполняется |
| Конвейер | байпас из стадий M и W (0/1/2 `nop` между зависимыми командами), приостановка после загрузки (load-use) для АЛУ, переходов, `jalr` и записи; сброс инструкций после перехода |
| Переходы | выполнение и невыполнение, вперёд и назад, адрес возврата `jal`/`jalr`, обнуление младшего бита адреса у `jalr` |
| Память | все смещения внутри слова, отрицательные смещения, знаковое расширение, байтовые стробы записи |
| Расширение M | знаки операндов, деление на 0 и переполнение `-2^31 / -1` по спецификации, старшие слова `mulh*`; зависимые цепочки `mul`→`mul`, `div`→`mul`, `mul`→`div`, запись в память и переход сразу по результату, инструкции за делением не теряются |
| BSRAM 16/32 кБайт | с `--imem-kb` и `--text-base` код проходит через границы кластеров, на них проверяется выбор кластера на выходе памяти |
| CSR (`csr.S`) | `csrrw/s/c` и варианты с константой, байпас результата и операнда, `mcycle`, поля и только читаемые CSR, `wfi`/`fence` как `nop` |
| Исключения (`trap.S`) | коды `mcause`, `mepc`, `mtval`; гашение записи в регистр и память; ловушка на зависимой загрузке и после перехода; `mstatus` при ловушке и `mret` |
| Прерывания (`irq.S`) | MSI, MTI, LI0 (STIM); маскирование `mstatus.MIE` и `mie`; векторный и прямой режим; приоритет MSI > MTI > LI0; точность ловушек под потоком прерываний, в том числе прерывание посреди деления |
| PLIC (`plic.S`) | `pending`, `claim`/`complete`, повторный запрос по уровню, приоритеты и порог, MEI через вектор 11, STIM как источник 1 |
| Отладчик (`dbg.S` + `tb_debug.svh`) | JTAG → DTM → DM: IDCODE, `dtmcs`, останов, `reset halt`, продолжение, регистры и CSR, ошибки `cmderr`, доступ к DMEM и IMEM, `ebreak` и шаг, см. [hw/info/debug.md](../info/debug.md#проверка) |

Ожидаемые значения вычисляет эталонная модель RV32IM в `tests/gen_rv32i.py`.

#### Устройство
| Файл | Назначение |
|------|-----------|
| `tb_core.sv` | Тестбенч: модуль `top.sv` целиком, загрузка программы в модели BSRAM, перехват TOHOST, трассы |
| `tb_debug.svh` | Сценарий отладчика: задачи JTAG (`jtag_ir`, `jtag_dr`), DMI и абстрактных команд, как их выполняет OpenOCD; включается `+dbgtest` |
| `gw_jtag_model.sv` | Поведенческая модель примитива GOWIN GW_JTAG (в библиотеке GOWIN модели нет), только для моделирования |
| `tests/riscv_test.h` | Макросы тестов и протокол обмена с тестбенчем (запись по адресу `TOHOST = 0x1F000000`) |
| `tests/gen_rv32i.py` | Генератор программ `tests/rv32i/*.S` |
| `tests/priv/*.S`, `priv_test.h` | Тесты CSR, исключений и прерываний (написаны вручную) |
| `tests/link.ld` | IMEM с `0x00000000` и DMEM с `0x10000000`; по адресу 0 переход на `_start`, код с `TEXT_BASE` |
| `run_tests.py` | Сборка программ, компиляция тестбенча, параллельный прогон, отчёт |
| `run_bench.py`, `bench/coremark/` | Бенчмарк CoreMark, см. [bench/README.md](bench/README.md) |

Программа загружается прямо в модели блоков BSRAM (`ram_MEM`) перед снятием сброса. На ПЛИС то же содержимое записывает в файл прошивки утилита `mergetool`.

Устройства моделирования есть только в тестбенче, их адреса лежат вне карты памяти `top.sv`:

| Адрес | Назначение |
|-------|-----------|
| `0x1F000000..08` | TOHOST: код завершения и аргументы (запись) |
| `0x1F00000C` | консоль: символ из младшего байта записи |
| `0x1F000014` | источники PLIC: бит N — уровень источника N (2…8) для `plic.S` |

Такты программа читает из CSR `mcycle`. `+leds=<файл>` пишет журнал переключений выходов GPIO: по нему проверялись примеры мигания светодиодом. `+trace=<файл>` пишет трассу записей в регистры и память. Трассы однотактного и конвейерного ядра на одной программе должны совпадать, если сравнивать записи в регистры и записи в память по отдельности.
