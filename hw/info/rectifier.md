Управляемый выпрямитель в ПЛИС: СИФУ, АЦП и ПИ-регуляторы
=========================================================

Законченная система управления трёхфазным мостовым тиристорным выпрямителем со стабилизацией выходного напряжения и ограничением тока (режим CV/CC). Вся система размещена в ПЛИС и собрана из типовых блоков askoRV32. Каждый блок работает и сам по себе, через процессор. Связи между блоками задаются в конфигураторе, а процессор пишет только задание (напряжение, ограничение тока) и параметры (коэффициенты, предел угла).

## Структура

```
            плата NSB (6 оптронов)                          тиристоры VS1..VS6
                    │                                              ▲
                    ▼                                              │
              ┌───────────┐  tick (строб: началась полуволна,      │
              │   SIFU    │──────── раз в 60 эл. град.) ──┐        │
              │ синхрони- │  run (импульсы идут)          │        │
              │ зация,    │──────────────────┐            │        │
              │ импульсы  │◄── u ────────────┼────────┐   │        │
              └───────────┘ угол = AMAX - u  │        │   │        │
                    └────────────────────────┼────────┼───┼────────┘
                                             │        │   │
       ADC_V (напряжение)  ┌──────────┐ win ◄┼────────┼───┤
       ───────────────────►│ ADC121   │      │        │   │
                           │ среднее  │ wmean│ ┌──────┴──────┐
                           │ за окно  │─────►│ │ PIREG PI_U  │ fb    задание Uзад (SP)
                           └──────────┘  fb  │ │ регулятор U │◄───── от процессора
                                             ├►│ run    lim  │
       ADC_C (ток)         ┌──────────┐ win ◄┼─┼─────────────┤
       ───────────────────►│ ADC121   │      │ └──────▲──────┘
                           │ среднее  │ wmean│        │ out PI_I (предел PI_U)
                           │ за окно  │──────┼─►┌─────┴───────┐
                           └──────────┘  fb  │  │ PIREG PI_I  │ задание Iогр (SP)
                                             └─►│ регулятор I │◄───── от процессора
                                           run  │ trk ◄── out PI_U
                                                └─────────────┘
```

| Блок | Роль в системе | Сам по себе (через процессор) |
|---|---|---|
| **SIFU** ([sifu/README.md](../src/periph/sifu/README.md)) | синхронизация от сети, импульсы на тиристоры; выход `tick` — граница окна усреднения (начало полуволны любой пары, 6 раз за период), выход `run` — импульсы идут (EN, сеть, синхронизация), вход `u` — управление: угол = AMAX − u (при `CR.UEXT`) | угол — регистр `ALPHA` (примеры 8, 10) |
| **ADC121** ×2 ([adc121/README.md](../src/periph/adc121/README.md)) | среднее напряжения и тока за окно 60 эл. град. (`win` ← `SIFU.tick`): пульсации 300 Гц шестипульсного моста усредняются целиком; выход `wmean` — код × 16 со стробом | отсчёты, среднее 2^N, окно по `CR.WCLOSE` (примеры 9, 10) |
| **PIREG** ×2 ([pireg/README.md](../src/periph/pireg/README.md)) | PI_U — регулятор напряжения, PI_I — регулятор тока; шаг — по каждому среднему за окно | шаг по команде `CR.STEP` с обратной связью в регистре |

## Прямые связи

Связи задаются в `.gwsoc`, в поле `links` блока-приёмника: `"вход": "БЛОК.выход"`. В конфигураторе это раздел «Прямые связи» в настройках блока: у каждого входа — список подходящих выходов других блоков. Генератор (`sw/socgen/socgen.py`) объявляет в `top.sv` цепи `lnk_<блок>_<выход>` и подаёт их на входы. Не подключённые входы получают константы, и блок работает через регистры.

| Выход | Вид | Входы, которые можно подключить |
|---|---|---|
| `SIFU.tick` | `stb` — строб на такт | `ADC121.win` |
| `SIFU.run` | `lvl` — уровень | `PIREG.run` |
| `ADC121.wmean` | `val` — 16 бит со стробом | `PIREG.fb` (значение и строб), `PIREG.lim`, `PIREG.trk`, `SIFU.u`, а строб — и на `ADC121.win` |
| `PIREG.out` | `val` | `SIFU.u`, `PIREG.lim`, `PIREG.trk`, `PIREG.fb` |

Конфигурация выпрямителя (так сделано в `fw/boards/tangprimer20k/tangprimer20k.gwsoc` и `tangnano9k.gwsoc`):

```json
{ "type": "sifu",   "name": "SIFU",  ..., "links": { "u": "PI_U.out" } },
{ "type": "adc121", "name": "ADC_V", ..., "wavg": true, "links": { "win": "SIFU.tick" } },
{ "type": "adc121", "name": "ADC_C", ..., "wavg": true, "links": { "win": "SIFU.tick" } },
{ "type": "pireg",  "name": "PI_U",  "omax": 3333, "links": { "fb": "ADC_V.wmean", "lim": "PI_I.out", "run": "SIFU.run" } },
{ "type": "pireg",  "name": "PI_I",  "omax": 3333, "links": { "fb": "ADC_C.wmean", "trk": "PI_U.out", "run": "SIFU.run" } }
```

Связь с несуществующим выходом, неподходящего вида или блока с самим собой — ошибка конфигуратора. В `soc.h` для каждого входа есть `<БЛОК>_LINK_<ВХОД>` (1 — подключён), чтобы программа могла проверить конфигурацию (`#if PI_U_LINK_FB`).

## Ход одного сектора (60 эл. град., 3,33 мс при 50 Гц)

1. Началась полуволна очередной пары → SIFU выдаёт `tick`, и пара фиксирует у себя действующий угол (AMAX − u).
2. `tick` закрывает окна ADC_V и ADC_C: в каждом около 1560 отсчётов (468 тыс./с на 20K) или 1310 (394 тыс./с на 9K). Последовательное деление суммы на число — 28 тактов. Затем строб `wmean` и значение — код × 16 (4 дробных бита).
3. Строб `wmean` запускает шаг PI_U и PI_I (4 такта, строб `out` — на 5-м). PI_U берёт предел `lim` = выход PI_I с прошлого шага, PI_I — предел интегратора `trk` = выход PI_U с прошлого шага.
4. Новый выход PI_U сразу идёт на вход `u` SIFU. Его берёт пара, чья полуволна начнётся следующей — через 60 эл. град.

Задержка от конца окна до нового угла — около 35 тактов шины (меньше 1 мкс). Регулятор работает с запаздыванием в один сектор, как и любая СИФУ с дискретной сменой угла. Процессор в контуре не участвует.

## Регулятор «напряжение с ограничением тока»

- **PI_U**: e = Uзад − U, выход u — тики угла (0 — угол 120°, AMAX — угол 0°). Верхний предел выхода — меньший из `OMAX` и выхода PI_I.
- **PI_I**: e = Iогр − I. Пока ток ниже ограничения, ошибка положительна и выход PI_I у верхнего предела: PI_U он не ограничивает, стабилизируется напряжение. Ток дошёл до ограничения — ошибка уходит в минус, выход PI_I падает ниже выхода PI_U и ограничивает его: стабилизируется ток.
- **Антинасыщение.**
  - Интегратор PI_U ограничен тем же пределом (выходом PI_I): при ограничении тока он не уходит вверх, и когда нагрузку снимают, напряжение не выбрасывается.
  - Интегратор PI_I ограничен выходом PI_U (`trk`): пока ограничения нет, интегратор тока «стоит» у текущего угла. Как только ток превысит Iогр, П-часть сразу опустит выход PI_I ниже выхода PI_U. Ток ограничивается за 1–3 сектора (тест: при набросе нагрузки ток выше 1,2 · Iогр — не дольше 3 секторов).
- **Пуск и стоп.** `SIFU.run` = 0 (EN снят, сети нет, нет синхронизации) держит оба регулятора в нуле. Пуск всегда идёт с угла 120°, напряжение нарастает с интегральной постоянной регулятора.
- **Нет измерения тока.** Если плата ADC_C не отвечает (кадры с ошибкой), её окна пустые, строба нет, PI_I не шагает и его выход остаётся 0. Тогда PI_U ограничен нулём, угол 120°: без измерения тока выпрямитель не открывается. Это проверено на 20K без питания ADC_C.

### Единицы — пересчитывает процессор

| Величина | В блоке | Пересчёт в программе |
|---|---|---|
| задание напряжения PI_U.SP | код АЦП ADC_V × 16 | `ADC121_MilliToCode16(ADC121_CAL(ADC_V), мВ)` — масштаб и смещение из конфигуратора |
| ограничение тока PI_I.SP | код АЦП ADC_C × 16 | `ADC121_MilliToCode16(ADC121_CAL(ADC_C), мА)` — с нулём платы 2049,3 |
| выход регуляторов, AMAX | тики ГПН угла | AMAX = 120 эл. град. по полупериоду сети: `SIFU_Deg10ToTicks(1200)` (3333 при 500 кГц, 50 Гц) |
| коэффициенты | K × 2^FRAC (FRAC = 12) | в примерах: число × 4096 |

### Коэффициенты по умолчанию и настройка

Коэффициент передачи объекта по напряжению: Ud = Ud0 · cos α. При 300 В линейного (ЛАТР стенда) Ud0 = 1,35 · 300 = 405 В. Вблизи α = 60°: dUd/dα = Ud0 · sin α ≈ 6,1 В на градус ≈ 0,22 В на тик (27,8 тика на градус). Плата ADC_V стенда — 0,222 В на код, итого около 1 кода на тик, то есть 16 единиц обратной связи на тик. Для апериодического выхода за 10–20 секторов:
- **PI_U**: KP = 0,02 (82), KI = 0,0125 (51) — петлевое усиление за шаг около 0,2;
- **PI_I**: при нагрузке десятки Ом ток меняется на 1–2 единицы обратной связи на тик, поэтому коэффициенты в 10 раз больше: KP = 0,2 (820), KI = 0,12 (500).

Это начальные значения. На стенде их подбирают под нагрузку командами `ku <KP> <KI>` и `ki <KP> <KI>` (примеры 10 и 11): уменьшить, если угол колеблется от сектора к сектору; увеличить, если напряжение подходит к заданию дольше 0,1 с. Усиление объекта растёт к α = 90° (sin α) и падает у 0° и 120°.

## Примеры

| | Пример 10 — регулятор программой | Пример 11 — регулятор в ПЛИС |
|---|---|---|
| Окна АЦП | закрывает SIFU (`win` ← `SIFU.tick`); без связи — программа по флагу `SR.SYNCF` | закрывает SIFU |
| Регулятор | на Си, те же формулы, что в PIREG (`soft_pi_step`), 300 шагов в секунду | блоки PI_U, PI_I |
| Угол | программа пишет `SIFU.ALPHA` | `SIFU.u` ← `PI_U.out`, `CR.UEXT` |
| Процессор | ждёт флаг `WRDY`, читает средние, считает, пишет угол (опрос в цикле) | пишет задание и коэффициенты, читает состояние для показа |
| Задержка «окно → угол» | десятки мкс (опрос, деление в Си, 64-битная арифметика при -O0) | ≈ 0,8 мкс |
| Зависит от программы | да: если программа задержится больше сектора, шаг пропадёт | нет |

Общее у обоих:
- задание напряжения `u 50.5` (В), ограничение тока `i 1.25` (А), коэффициенты `ku`/`ki`;
- на стенде импульсы включают DI1 (сеть) и DI2 (имитатор), как в примере 8; без стенда — команды `e` и `s`;
- TM1638 по кругу показывает угол, ток и напряжение; кнопки 6/7/8 удерживают показание, кнопки 1, 2 меняют задание напряжения на ±1 В;
- светодиод 5 — ограничение тока.

В примере 11 есть команда `fi <код × 16>`: шаг PI_I программой (`PIREG_Step`). Она показывает, что блок работает и через процессор, и даёт проверить цепочку PI_U → SIFU без платы тока.

Пример выбирается в Eclipse флагом `-DEXAMPLE=10` или `11`. На стенде 9K по умолчанию — пример 12: режимы по DI (DI1 — имитатор и угол вручную, DI2 — сеть и угол вручную, DI3 — регулирование PIREG) и меню на кнопках TM1638; на 20K — пример 9. На стенде вход синхронизации CA (вывод 13) не работает, поэтому в DI3 синхронизация теряется и регуляторы стоят (угол 120°); на плате ADC_C бывают эпизоды односторонней помехи (+2…6 кодов в окне).

Регуляторы и окна стоят около 1170 ячеек. На 9K со всей прежней периферией они не помещались: не хватило 13 ячеек. Поэтому со стенда убраны блоки STIM и SPIFLASH (внешняя флеш только для данных; примеры 8, 10, 11 их не используют). Вернуть их можно, если отключить, например, окна или один регулятор. Запас по частоте ядра на 9K маленький (1,2 %); при следующих добавлениях понадобится упрощать логику или снижать частоту.

## Проверка

- Тесты блоков: `tb_pireg` (53 проверки, в том числе замкнутый контур CV/CC на модели выпрямителя), `tb_adc121` (86, среднее за окно с дробной частью, пустое окно, прерывание), `tb_sifu` (130: `tick` 6 раз за период, `run`, угол AMAX − u, u > AMAX → угол 0, возврат к ALPHA).
- На Tang Primer 20K (имитатор сети, ADC_V — внешние 45 В, контур не замкнут):
  - пример 10 — 300 шагов в секунду, угол уходит в нужную сторону (задание 30 В → 120°, 60 В → 0°);
  - пример 11 — цепочка `SIFU.tick` → окна → PI_U работает в ПЛИС, 300 шагов в секунду, ошибка PI_U верная (+360 / −1082 единиц при 50 / 30 В задания).
  - Без платы тока PI_U ограничен нулём (угол 120°). После `fi 0` выход PI_I = AMAX, и выход PI_U прямо управляет углом СИФУ: при 60 В — 0°, при 30 В — 120°.
- Стенд 9K: примеры 10 и 11 стартуют; без DI1/DI2 регуляторы стоят. Замкнутый контур на силовой части ещё не проверен: силовой мост не подключён.
