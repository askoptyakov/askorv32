Пользовательская периферия askoRV32
===================================

Здесь лежат устройства, которые подключаются к процессору снаружи, на порт шины регистров `per_*` (`hw/src/cpu.sv`). Системные устройства — память, CLINT, PLIC, мультиплексор шины — часть процессора и лежат в `hw/src/sys/`.

| Папка / файл | Что это |
|---|---|
| `periph_regs.sv` | шаблон регистровой части устройства: `periph_regs` (стробы по регистрам, данные чтения) и `periph_reg` (регистр с байтовой записью) |
| `periph_tb.svh` | общая часть тестов: такт, сброс, ведущий шины регистров (`bus_wr`, `bus_wrb`, `bus_rd`), проверки (`check`, `check_rd`), итог |
| `stim/` | таймер STIM (счёт вверх/вниз, ШИМ, прерывание) |
| `gpio/` | дискретные входы/выходы |
| `tm1638/` | плата индикации LED&KEY на TM1638 |

## Устройство — это папка

```
periph/<устройство>/
    <устройство>.sv      - модуль(и) устройства
    tb_<устройство>.sv   - тест через шину регистров (может быть несколько tb_*.sv)
    README.md            - описание: как работает, регистры, что записывать, библиотека на Си, примеры, тест
```

Тесты всех устройств:

```
py hw/sim/run_periph_tests.py
```

Тест одного — `py hw/sim/run_periph_tests.py stim`; с временными диаграммами — `--vcd` (файлы в `hw/sim/build`). Тест собирается из всех `.sv` папки устройства, `periph_regs.sv` и `periph_tb.svh`. От ядра и конфигурации платы он не зависит.

Тесты ядра — отдельно: `py hw/sim/run_tests.py`. Они моделируют процессор `cpu.sv` без периферии платы.

## Как сделать новое устройство

1. **Правила шины** — `hw/info/architecture.md`, раздел «Шина данных и периферии»:
   - запись выполняется в такте обращения;
   - данные чтения выдаются из регистра на следующем такте (`MEMORY_TYPE = 1`);
   - ожиданий нет: всё медленное прячется за флагами «занято / готово».
2. **Порты** — как у всех устройств: `clk`, `rst`, `Write[3:0]`, `Addr`, `WData`, `RData` и при необходимости `Read` (строб чтения — для FIFO и флагов «сброс чтением»), затем выводы и `irq`.
3. **Регистровая часть — по шаблону:**
   ```systemverilog
   logic [N-1:0][3:0] we;  logic [N-1:0] re;  logic [31:0] wdata;
   periph_regs #(.N(N), .MEMORY_TYPE(MEMORY_TYPE)) regs
       (.clk(clk), .Write(Write), .Read(Read), .Addr(Addr), .WData(WData), .RData(RData),
        .we(we), .re(re), .wdata(wdata), .rdata({ ... значения регистров N-1..0 ... }));
   periph_reg #(.W(16)) r_cfg (.clk(clk), .rst(rst), .we(we[0]), .wdata(wdata), .q(cfg));
   ```
   Флаги, команды и FIFO — своя логика по `we[i]`, `re[i]`, `wdata`. Образец — `stim/stim.sv`.
4. **Запрос прерывания** — через регистр (на такт позже события), чтобы путь к решению о ловушке в ядре был коротким. Подключение — на линию LI*N* (`irq_local`) или к источнику PLIC (`irq_src`).
5. **Тест** `tb_<устройство>.sv`:
   ```systemverilog
   module tb_uart;
       localparam string DEV = "uart";
       `include "periph_tb.svh"
       uart_top #(.MEMORY_TYPE(1'b1)) dut (.clk(clk), .rst(rst), .Write(Write), .Read(Read),
                                           .Addr(Addr), .WData(WData), .RData(RData), ...);
       initial begin
           reset_dut();
           check_rd(32'h00, 0, "сброс: CR");
           bus_wr(32'h00, 32'h1);
           ...
           finish_tests();
       end
   endmodule
   ```
6. **`README.md`** — по образцу `stim/README.md`: подключение и параметры, регистры, как работает, библиотека на Си, примеры, что проверяет тест.
7. **Подключение к плате:**
   - файл устройства — в `hw/riscv.gprj` (из него же берёт исходники сборка через `socgen`);
   - блок устройства — в генератор `sw/socgen/socgen.py` и конфигуратор (`web/app.js`), чтобы его можно было включить в `fw/riscv.gwsoc`;
   - регистры для прошивки — в `fw/Core/Inc/periphery.h`, библиотека — в `fw/Core/`.
