Пользовательская периферия askoRV32
===================================

Здесь лежат устройства, которые подключаются к процессору снаружи, на порт шины регистров `bus_per` (`hw/src/cpu.sv`). Системные устройства — память, CLINT, PLIC, мультиплексор шины — часть процессора и лежат в `hw/src/sys/`.

| Папка / файл | Что это |
|---|---|
| `periph_regs.sv` | шаблон регистровой части устройства: `periph_regs` (стробы по регистрам, данные чтения) и `periph_reg` (регистр с байтовой записью) |
| `periph_tb.svh` | общая часть тестов: такт, сброс, ведущий шины регистров (`bus_wr`, `bus_wrb`, `bus_rd`), проверки (`check`, `check_rd`), итог |
| `stim/` | таймер STIM (счёт вверх/вниз, ШИМ, прерывание) |
| `gpio/` | дискретные входы/выходы |
| `tm1638/` | плата индикации LED&KEY на TM1638: HEX, текст cp1251 (кириллица) через знакогенератор в BSRAM |
| `uart/` | приёмопередатчик UART: FIFO, прерывания по заполнению FIFO, чётность, 1–2 стоп-бита |
| `adc121/` | АЦП ADC121S051 — аналоговые измерения на платах ADC_V (напряжение) и ADC_C (ток): кадр с проверкой, период отсчётов, усреднение 2^N и среднее за окно (прямая связь `win` → `wmean`), пересчёт в единицы |
| `sifu/` | СИФУ трёхфазного мостового тиристорного выпрямителя: синхронизация от платы NSB, пила на пару фаз, угол управления, сдвоенные импульсы на VS1…VS6, имитатор сети; прямые связи `tick`, `run`, `u` |
| `pireg/` | ПИ-регулятор (один контур): задание, KP, KI, предел, антинасыщение; через процессор или прямыми связями (обратная связь, внешние пределы `lim`/`trk`, стоп `run`) — из двух блоков собран регулятор выпрямителя CV/CC ([hw/info/rectifier.md](../../info/rectifier.md)) |
| `spiflash/` | внешняя SPI-флеш: обмен с флеш из программы и аппаратный загрузчик программы в IMEM/DMEM (порт `boot_*` процессора); модель флеш для тестов — `spiflash/sim/` |

## Устройство — это папка

```
periph/<устройство>/
    <устройство>.sv      - модуль(и) устройства
    tb_<устройство>.sv   - тест через шину регистров (может быть несколько tb_*.sv)
    README.md            - описание: как работает, регистры, что записывать, библиотека на Си, примеры, тест
```

Тесты всех устройств:

```
py hw/sim/run_periph_tests.py
```

Тест одного — `py hw/sim/run_periph_tests.py stim`; с временными диаграммами — `--vcd` (файлы в `hw/sim/build`). Тест собирается из всех `.sv` папки устройства (и её подпапки `sim/` — модели внешних микросхем, в проект ПЛИС не входят), `periph_regs.sv` и `periph_tb.svh`. От ядра и конфигурации платы он не зависит.

Тесты ядра — отдельно: `py hw/sim/run_tests.py`. Они моделируют процессор `cpu.sv` без периферии платы.

## Как сделать новое устройство

1. **Правила шины** — `hw/info/architecture.md`, раздел «Шина данных и периферии»:
   - запись выполняется в такте обращения;
   - данные чтения выдаются из регистра на следующем такте (`MEMORY_TYPE = 1`);
   - ожиданий нет: всё медленное прячется за флагами «занято / готово».
2. **Порты** — как у всех устройств: `clk`, `rst`, `Write[3:0]`, `Addr`, `WData`, `RData` и при необходимости `Read` (строб чтения — для FIFO и флагов «сброс чтением»), затем выводы и `irq`.
3. **Регистровая часть — по шаблону:**
   ```systemverilog
   logic [N-1:0][3:0] we;  logic [N-1:0] re;  logic [31:0] wdata;
   periph_regs #(.N(N), .MEMORY_TYPE(MEMORY_TYPE)) regs
       (.clk(clk), .Write(Write), .Read(Read), .Addr(Addr), .WData(WData), .RData(RData),
        .we(we), .re(re), .wdata(wdata), .rdata({ ... значения регистров N-1..0 ... }));
   periph_reg #(.W(16)) r_cfg (.clk(clk), .rst(rst), .we(we[0]), .wdata(wdata), .q(cfg));
   ```
   Флаги, команды и FIFO — своя логика по `we[i]`, `re[i]`, `wdata`. Образец — `stim/stim.sv`.
4. **Запрос прерывания** — через регистр (на такт позже события), чтобы путь к решению о ловушке в ядре был коротким. По умолчанию устройство — источник PLIC (`irq_src`, номера по порядку блоков в конфигураторе); локальная линия LI*N* (`irq_local`) — по выбору в конфигураторе, для особо быстрых случаев.
5. **Тест** `tb_<устройство>.sv`:
   ```systemverilog
   module tb_uart;
       localparam string DEV = "uart";
       `include "periph_tb.svh"
       uart_top #(.MEMORY_TYPE(1'b1)) dut (.clk(clk), .rst(rst), .Write(Write), .Read(Read),
                                           .Addr(Addr), .WData(WData), .RData(RData), ...);
       initial begin
           reset_dut();
           check_rd(32'h00, 0, "сброс: CR");
           bus_wr(32'h00, 32'h1);
           ...
           finish_tests();
       end
   endmodule
   ```
6. **`README.md`** — по образцу `stim/README.md`: подключение и параметры, регистры, как работает, библиотека на Си, примеры, что проверяет тест.
7. **Подключение к плате:**
   - файл устройства — в проекты плат `hw/boards/*/riscv.gprj` (из него же берёт исходники сборка через `socgen`);
   - тип устройства — в генератор `sw/socgen/socgen.py` и конфигуратор `sw/socgen/web/app.js` (`TYPES` и др., см. [sw/socgen/README.md, «Новый блок периферии»](../../../sw/socgen/README.md#новый-блок-периферии)): тогда его можно добавить из библиотеки конфигуратора, а `README.md` устройства будет описанием модуля;
   - регистры для прошивки (`<ТИП>_TypeDef`, биты) — в заголовке драйвера `fw/Core/Inc/<устройство>.h`, библиотека — в `fw/Core/`; адрес и указатель создаёт конфигуратор в `soc.h`.
