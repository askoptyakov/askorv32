TM1638 — плата индикации
========================

Контроллер платы LED&KEY на микросхеме TM1638: 8 семисегментных цифр, 8 светодиодов и 8 кнопок. Программа пишет значения в регистры, а контроллер сам постоянно обновляет индикацию и опрашивает кнопки по трёхпроводному интерфейсу (STB, CLK, DIO). Цифры выводятся в одном из трёх режимов: HEX (8 шестнадцатеричных цифр), TEXT (8 символов cp1251, в том числе кириллица, через знакогенератор в ПЛИС) и RAW (сегменты как есть).

| Файл | Назначение |
|---|---|
| `tm1638.sv` | модуль `tm1638_top` (регистры по шаблону `periph_regs`), `tm1638_board_controller` (автомат обмена), `tm1638_sio` (последовательный интерфейс); контроллер — по мотивам A. Kirichenko и A. Garfield |
| `tm1638_font.sv` | знакогенератор `tm1638_font`: ПЗУ 256 × 8 (код cp1251 → сегменты), один блок BSRAM; **файл создаёт `gen_font.py`** |
| `gen_font.py` | таблица начертаний символов; создаёт `tm1638_font.sv` и `font.md`: `py hw/src/periph/tm1638/gen_font.py` |
| `font.md` | какие символы есть и как они выглядят (создаёт `gen_font.py`) |
| `tb_tm1638.sv` | тест с моделью микросхемы: `py hw/sim/run_periph_tests.py tm1638` |
| `fw/Core/Inc/tm1638.h`, `fw/Core/Src/tm1638.c` | библиотека на Си |

## Подключение

Подключает конфигуратор ПЛИС (блок TM1638 в `fw/boards/<плата>/<плата>.gwsoc`): окно адресов — по умолчанию `0x1200_0000`, выводы DIO, CLK, STB.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `MEMORY_TYPE` | 0 | 1 — данные чтения на следующем такте (шина с BSRAM), 0 — в том же такте |
| `CLK_MHZ` | 27 | частота `clk`, МГц (целая часть). От неё — делитель интерфейса (не выше 700 кГц) и пауза строба 1 мкс. Конфигуратор подставляет частоту шины периферии |

| Порт | Смысл |
|---|---|
| `clk`, `rst` | такт и сброс шины периферии |
| `Write`, `Addr`, `WData`, `RData` | шина регистров |
| `tm_stb`, `tm_clk` | выходы строба и такта интерфейса |
| `tm_dio` | двунаправленная линия данных |

## Регистры

| Смещение | Имя | Доступ | Смысл |
|---|---|---|---|
| `0x00` | `SEGS` | чтение/запись | 8 цифр HEX: тетрада 0 — правая цифра, тетрада 7 — левая |
| `0x04` | `LEDS` | чтение/запись | светодиоды, бит 0 — LED1 |
| `0x08` | `KEYS` | чтение | кнопки, бит 0 — S1; обновляется в каждом кадре опроса |
| `0x0C` | `CTRL` | чтение/запись | `[1:0] MODE`: 0 — HEX (`SEGS`), 1 — TEXT (коды символов из `TEXT0/TEXT1`), 2 — RAW (байты `TEXT0/TEXT1` — сегменты); `[15:8] DOTS` — точка после символа, бит *i* — позиция *i* слева (во всех режимах) |
| `0x10` | `TEXT0` | чтение/запись | символы 0..3: байт 0 — левый символ |
| `0x14` | `TEXT1` | чтение/запись | символы 4..7: байт 3 — правый символ |

После сброса все регистры записи — 0: режим HEX, индикатор показывает `00000000`. До 2026-09-30 регистры не сбрасывались.

## Как работает

Кадр повторяется непрерывно:
1. Чтение кнопок: команда `0x42`, затем 4 байта от микросхемы. В байте *n* бит 0 — кнопка 8−*n*, бит 4 — кнопка 4−*n*.
2. Команда записи с автоинкрементом адреса `0x40`.
3. Адрес `0xC0` и 16 байт: цифра, светодиод, цифра… (от левой цифры к правой, семисегментный код `gfedcba`).
4. Включение индикатора с полной яркостью `0x8F`.

**Режимы цифр.** Сегменты очередной цифры выбираются по `CTRL.MODE`: HEX — тетрада `SEGS` через таблицу 0–F, TEXT — байт `TEXTn` как адрес знакогенератора, RAW — байт `TEXTn` как есть (бит 0 — a, …, 6 — g, 7 — точка h). Затем добавляется точка из `DOTS`. Знакогенератор — синхронное ПЗУ в одном блоке BSRAM (`syn_romstyle = "block_rom"`), поэтому номер цифры, её тетрада и байт задержаны на такт, чтобы прийти вместе с данными ПЗУ.

**Знакогенератор.** Коды — cp1251, кодировка файлов прошивки: строка `"ПРИВЕТ"` в исходнике на Си уже готова для `TEXT0/TEXT1`. Есть цифры, латиница, кириллица А–я, Ё/ё и основные знаки; символы, которые на 7 сегментах не изобразить, гаснут. Похожие буквы неизбежно совпадают (`Н` и `Х`, `В` и `8`). Полный список — `font.md`. Чтобы поменять начертание, правят таблицу в `gen_font.py` и запускают его — он перепишет `tm1638_font.sv` и `font.md`.

Байты передаются младшим битом вперёд. Микросхема принимает бит по фронту CLK. Кадр — 24 байта по 8 бит при частоте интерфейса ~350 кГц, около 0.6 мс при частоте шины 45 МГц. Новое значение появляется на индикаторе в пределах одного кадра.

## Библиотека на Си (`tm1638.h`)

| Функция | Действие |
|---|---|
| `TM1638_WriteSegs(value)` | 8 цифр HEX (включает режим HEX) |
| `TM1638_WriteText(s)` | до 8 символов cp1251 слева, остаток — пробелы; `.` или `,` после символа — его точка, позицию не занимает (включает режим TEXT) |
| `TM1638_WriteNumber(v)` | число со знаком, выровненное вправо (режим TEXT) |
| `TM1638_WriteRaw(segs[8])` | сегменты 8 позиций слева направо (режим RAW) |
| `TM1638_SetMode(mode)`, `TM1638_SetDots(mask)` | режим (`TM1638_MODE_HEX/TEXT/RAW`), точки |
| `TM1638_WriteLeds(mask)`, `TM1638_WriteLed(led, state)` | светодиоды |
| `TM1638_ReadKeys()`, `TM1638_ReadKey(key)` | кнопки |

## Пример

```c
#include "tm1638.h"

TM1638_WriteSegs(0x12345678);          //на индикаторе 12345678
TM1638_WriteText("ПРИВЕТ-1");          //кириллица: строка в cp1251
TM1638_WriteText("t=36.6");            //точка после 6, на индикаторе «t=36.6  »
TM1638_WriteNumber(-1250);             //«   -1250»
TM1638_WriteLed(TM1638_LED0, TM1638_PIN_SET);
if (TM1638_ReadKey(TM1638_KEY0)) { /* нажата S1 */ }
```

## Тест (`tb_tm1638.sv`)

56 проверок. Модель микросхемы в тестбенче декодирует посылки и отвечает кнопками:
- регистры: сброс, разрядность `LEDS`, байтовая запись, `KEYS` только для чтения;
- команды кадра `0x42`, `0x40`, `0xC0` + 16 байт, `0x8F`;
- семисегментные коды всех 8 цифр и 8 светодиодов для записанных значений;
- сборка `KEYS` из ответа модели для двух комбинаций кнопок;
- режим TEXT: кадр «ПРИВЕТ-1» (коды знакогенератора для кириллицы и знака), режим RAW, точка из `DOTS` в режиме HEX.

Бегущая строка и кнопки — пример 6 в `fw/Core/Src/main.c`.
