Конфигуратор ПЛИС askoRV32 (socgen)
====================================

Визуальная настройка проекта ПЛИС из проекта прошивки в Eclipse — по образцу CubeMX у STM32. ПЛИС - одна из двух:
GW1NR-LV9QN88P (Tang Nano 9K) или GW2A-LV18PG256 (Tang Primer 20K), выбирается в шапке конфигуратора. Платы проекта и
их файлы - [hw/boards/README.md](../../hw/boards/README.md).

Источник правды — файл платы `fw/boards/<плата>/<плата>.gwsoc` (JSON: [Tang Nano 9K](../../fw/boards/tangnano9k/tangnano9k.gwsoc),
[Tang Primer 20K](../../fw/boards/tangprimer20k/tangprimer20k.gwsoc)). Плату описывают разделы `board` (название, конфигурация
сборки Eclipse, имя для openFPGALoader) и `device` (номер детали ПЛИС), каталоги - `paths` (`hw` - каталог платы
`hw/boards/<плата>`, `src` - общие исходники `hw/src`). По нему генерируются:

| Файл | Что в нём |
|------|-----------|
| `hw/boards/<плата>/top.sv` | верхний уровень: порты-выводы, параметры `cpu`, карта адресов и memmux пользовательской периферии на порту `bus_per`, экземпляры устройств и подключение их прерываний. **Не редактировать вручную** |
| `hw/boards/<плата>/riscv.cst` | назначение выводов `IO_LOC` / `IO_PORT` и их стандарты I/O |
| `fw/boards/<плата>/soc.h` | описание ПЛИС для прошивки: плата и ПЛИС (`SOC_BOARD`, `SOC_FPGA`, `SOC_FPGA_EMBEDDED_FLASH`), `SYSCLK_HZ`, ядро и память; для каждого блока — `<ИМЯ>_BASE`, указатель `<ИМЯ>` и настройки `<ИМЯ>_xxx`; `<ТИП>_PRESENT`/`_COUNT`; `PLIC_SRC_Type` и имена обработчиков; системные `CLINT`, `PLIC` (адреса и указатели); имена выводов GPIO `<ЦЕПЬ>_PIN`/`_PORT`, шины `_MSK`/`_POS` (cp1251, CRLF — как файлы прошивки). Путь — `paths.soc` в `.gwsoc` (`soc.h` рядом с ним) |
| `hw/boards/<плата>/impl/pnr/riscv.fs` | битовый поток Gowin EDA (маршрут по умолчанию), при сборке |
| `hw/boards/<плата>/impl_oss/riscv.fs` | битовый поток открытого маршрута (Yosys + nextpnr-himbaechel + apicula), при сборке |

Кроме того, генератор выставляет кристалл в проекте Gowin `hw/boards/<плата>/riscv.gprj` (элемент `Device`) и напряжение ядра `VCC` в
настройке процесса (GW1NR-9 - 1.2 В, GW2A-18 - 1.0 В), а в `top.sv` - параметр `PLL_DEVICE` (кристалл для rPLL в `clk_pll`).

Процессор — такт (rPLL), сброс, ядро, отладчик JTAG, IMEM и DMEM, CLINT, PLIC и системная шина — в [`hw/src/cpu.sv`](../../hw/src/cpu.sv); его правят вручную. Имена сигналов, экземпляров и параметров `top.sv` зарезервированы: цепь с таким именем конфигуратор не примет.

## Состав

| Путь | Назначение |
|------|------------|
| `web/` | страница конфигуратора: изображение микросхемы, блоки, диалоги (`index.html`, `app.js`, `style.css`) |
| `web/devices.js` | кристаллы: выводы корпусов QFN88P (GW1NR-9C) и PBGA256 (GW2A-18C) с банками и функциями (из Gowin IDE `data/device/*/*.json`) и свойства семейств - пределы rPLL, блоки BSRAM, встроенная flash, выводы двойного назначения, VCC, маршрут apicula. Создаёт `mkdevices.py` |
| `mkdevices.py` | сборка `web/devices.js` из файлов Gowin IDE и таблицы семейств (`py sw/socgen/mkdevices.py`); новый кристалл - строка в `FAMILIES` |
| `socgen.py` | генератор и сборка открытым маршрутом |
| `eclipse/` | плагин Eclipse: редактор `.gwsoc` (страница `web/` во встроенном Edge), команды «Конфигуратор ПЛИС» и «Программатор ПЛИС» (окно записи и очистки памяти ПЛИС, `ProgrammerDialog.java` → `sw/fpgaload/fpgaload.py`), `build.py` |

Правила — выбор адресов, расчёт rPLL, номера прерываний, делитель UART, стандарты выводов, проверки — записаны и в `web/app.js`, и в `socgen.py`. Меняя их, правьте оба файла.

## Работа в Eclipse

Установка плагина — [sdk/SETUP.md, п. 11](../../sdk/SETUP.md#11-плагин-конфигуратор-плис-для-eclipse). Файл платы `boards/<плата>/<плата>.gwsoc` открывается двойным щелчком в Project Explorer, либо командой **Конфигуратор ПЛИС** в меню проекта (если плат несколько - она спросит, какую). Команда **Программатор ПЛИС** открывает окно записи (SRAM, встроенная flash, внешняя SPI-флеш) и очистки (встроенная flash, SPI-флеш) — [sdk/SETUP.md, п. 8.5](../../sdk/SETUP.md#85-загрузка-плис-из-eclipse-openfpgaloader-external-tools).

### Схема

Слева — микросхема. QFN (Tang Nano 9K): номера выводов внутри корпуса, имена цепей снаружи, цвет ячейки — банк, кружка — группа блока. BGA (Tang Primer 20K): сетка 16×16 шариков, буквы рядов слева, номера столбцов сверху; в шарике - его имя (H11) и коротко имя цепи, цвет шарика - банк, кольцо - группа блока. Внутри корпуса блоков нет (у корпусов BGA выводы занимают всё поле). Справа — структура: процессор (`CPU`) и такт (`PLL`) — серые; шина данных **`bus_per`** (сплошная) и шина тактирования **`clk_per`** (пунктир) идут к каждому устройству. Устройства — цветом группы: **интерфейсы** (UART, SPIFLASH) — синие, **GPIO** — бирюзовые, **своя периферия** (STIM, TM1638, SIFU) — фиолетовые. В шапке блока — его имя латиницей, внутри — короткое описание по-русски и номер прерывания, справа — порты латиницей (`TX`, `RX`, `IO0`, `PWM`…) с выводами.

- **Подсветка.** Наведение на блок или его выбор подсвечивает его выводы на микросхеме; остальные выводы, включая питание, приглушаются.
- **Выводы на схеме.** Щелчок по номеру вывода — список выводов (свободные сверху), щелчок по имени цепи — переименование на месте; «+» — назначить вывод, добавить линию GPIO, вывести ШИМ STIM. При переносе сигнала на другой вывод имя цепи переходит вместе с ним.
- **Микросхема.** Двойной щелчок по выводу — сигнал и стандарт I/O; по имени цепи — переименование; по корпусу — снова видны все выводы. Вывод можно **перетащить** на другой: сигналы, имя цепи и стандарт I/O переходят на него, с занятым выводом — обмен (на выводы питания и JTAG — нельзя). Внизу — таблица «Назначения выводов» (как I/O Constraints во FloorPlanner).
- **Шапка.** Слева — инструменты поля (добавить блок, масштаб), справа — сборка (стандарты I/O, сохранить, маршрут, Place, «Собрать» с молотком), под ней — ресурсы. На время сборки ресурсы сменяет шкала хода со временем, кнопка «Собрать» неактивна; консоль Eclipse сама не открывается.
- **Ресурсы** (занято/всего) — справа вверху: занятые логические ячейки, регистры, блоки BSRAM, DSP, выводы I/O, rPLL и Fmax ядра; подпись — при наведении. Логика, регистры, DSP и Fmax — по последней сборке (`hw/boards/<плата>/impl/socgen/resources.json`), BSRAM, выводы и PLL — сразу по конфигурации. Жёлтый — занято больше 75 %, красный — больше 90 % или Fmax ниже частоты rPLL.

### Периферия — из библиотеки

В новом проекте пользовательских блоков нет. **«+ Добавить блок»** открывает библиотеку: устройства по группам с кратким описанием. **«Описание»** показывает README.md модуля (`hw/src/periph/<тип>/README.md`: регистры, работа, примеры), **«Добавить»** ставит блок в проект. Блоков одного типа может быть сколько угодно: когда добавляется второй UART, первый становится `UART0`, новый — `UART1`; когда блок типа остаётся один, он снова без номера (`UART`). Имена можно сменить. Имя блока — это и указатель на регистры в Си (`UART1->DIV`), и `UART1_BASE`, и `PLIC_UART1_IRQHandler`; в `top.sv` — его строчная форма (`uart1`). Первый блок типа может носить имя типа (`UART`) — с ним работают драйверы (`uart.c`); если у первого блока другое имя, `soc.h` делает имя типа его синонимом.

### Настройки — справа

Щелчок по блоку (на любом виде) открывает его настройки на правой панели вместо карты адресов; ✕ — назад к карте. Изменения применяются сразу.

- **Устройство:** имя, адрес регистров (авто или вручную), прерывание (у STIM и UART), свои параметры (разрядность STIM; скорость, чётность, стоп-биты, FIFO и расчёт делителя UART), выводы с именами цепей, «Описание модуля», «Удалить блок».
- **SIFU** (СИФУ выпрямителя): 6 входов платы синхронизации NSB (`AB`…`AC`) и 6 выходов на тиристоры (`VS1`…`VS6`); частота пилы (по умолчанию 500 кГц — генератор считает делитель `DIV_INIT`), «Сдвиг DELAY» (`DELAY_RC_COMPENSATION`, 400), «Импульс» (150 тиков), «Имитатор сети» (есть/нет, `SIM_EN`). Под полями — делитель, тиков на полупериод 50 Гц, DELAY и импульс в градусах, наибольший угол; проверки: угол до 120° укладывается в пилу (предупреждение), полупериод меньше 8192 тиков (ошибка). Описание — [hw/src/periph/sifu/README.md](../../hw/src/periph/sifu/README.md).
- **«Такт и сброс»:** кварц и его вывод (★ — GCLK и входы PLL), rPLL по частоте или вручную с проверкой PFD, VCO и CLKOUT, вывод сброса.
- **«Процессор»:** тип ядра, расширение M и бит частного за такт, регистровый файл (`core.rfType`, параметр `RF_TYPE`: `"lut"` — 0; `"bsram"` — 2, чтение по спаду в стадии D; `"bsram-edge"` — 1, чтение на фронте D → E, для сравнения; BSRAM только у конвейера, +2 блока; для GW2A-18 рекомендуется, для GW1NR-9 нет — шаги 21, 22 в `hw/info/performance_roadmap.md`), IMEM и DMEM, отладчик JTAG, число источников PLIC; частота шины периферии и занятые блоки BSRAM (вместе со шрифтами TM1638 и регистровым файлом).

**Прерывания:** **PLIC** (по умолчанию; источники 1, 2… в порядке блоков в проекте), **локальная линия LI*n*** или «не подключено». В прошивку — через `soc.h`: `PLIC_SRC_UART`, `#define PLIC_UART_IRQHandler PLIC_SRC2_IRQHandler` или `UART_IRQn`/`UART_IRQHandler`.

### Имена цепей — имена в Си

Имя цепи — это одновременно имя порта ПЛИС (`top.sv`, `riscv.cst`) и define в прошивке, поэтому пишется **заглавными** (`LED0`, `UART_TX`); ввод переводится в заглавные сам. Для выводов GPIO `soc.h` получает `<ИМЯ>_PIN` (номер линии) и `<ИМЯ>_PORT` (блок GPIO): цепь `LED3` — `LED3_PIN`, `LED3_PORT`; цепь `LED[3]` — тоже `LED3`. Шина `LED[0]…LED[5]` на одном блоке — `LED_MSK`, `LED_POS`, `LED_PORT`. Работа по имени — макросы `gpio.h`:

```c
GPIO_MODE(LED3, GPIO_MODE_OUTPUT);
GPIO_WRITE(LED3, GPIO_PIN_SET);
GPIO_TOGGLE(LED0);
if (GPIO_READ(BUTTON)) { ... }
GPIO_MODE_BUS(LED, GPIO_MODE_OUTPUT);
GPIO_WRITE_BUS(LED, 0x15);          //значение в разряды шины LED[...], остальные линии блока не меняются
```

Сменили имя цепи — после «Собрать» поменяются и имена в `soc.h`. Две цепи, дающие одно имя в Си (`LED3` и `LED[3]`), — ошибка. Имя цепи кварца — порт, на который ссылается `create_clock -name clk` в `riscv.sdc`: генератор правит это имя в `riscv.sdc` сам.

### Сборка

- **«Стандарты I/O…»** — общие значения и значения по банкам (`"banks"` в `.gwsoc`). Порядок: свои настройки вывода → банк → общие. На Tang Nano 9K банки 1–2 — 3,3 В (LVCMOS33), банк 3 — 1,8 В (LVCMOS18).
- **Маршрут** — список рядом с «Собрать»: **Gowin EDA** (по умолчанию) или **apicula**. **Place** — `Place_Option` размещения Gowin EDA: 0 — быстрее компиляция, 1 — лучше трассируемость, 2 — лучше тайминги; «как в проекте» — не менять. **Загрузка** — Loading Rate Gowin EDA: частота, с которой ПЛИС при включении питания читает свой битовый поток из флеш (встроенной — AUTO BOOT, внешней — MSPI; для SRAM не важна). У GW1N-9 — 250 МГц / N: 2.5 (по умолчанию), 5.435 … 25, 31.25, 41.667, 62.5 МГц (SUG100, табл. 4-3). Битовый поток 442 кБайт читается при 2.5 МГц ~1.4 с, при 25 МГц ~0.15 с ([hw/info/flash_speed.md](../../hw/info/flash_speed.md#время-старта-плис-из-внешней-флеш)). apicula частоту не задаёт (всегда 2.5 МГц, генератор предупреждает). Выбор хранится в `.gwsoc` (`"build": { "toolchain": ..., "placeOption": ..., "loadingRate": "25.000" }`); перед сборкой генератор записывает `Place_Option` и `DOWNLOAD_SPEED` (`"default"` или `"250/N"`) в `hw/boards/<плата>/impl/riscv_process_config.json`. Частота попадает в заголовок битового потока (`//LoadingRate: 25.000MHz` в `riscv.fs`).
- **«Собрать»** — сохранить файл, сгенерировать `top.sv`, `riscv.cst`, `soc.h` и собрать битовый поток. Ход сборки в процентах — полоса в шапке конфигуратора и индикатор задачи Eclipse (генератор выводит строки `@@PROGRESS <проценты> <этап>`: у Gowin EDA — по отметкам синтеза и размещения, у apicula — по этапам), подробности — в консоли «askoRV32 - сборка ПЛИС».
- **Панели.** Пока вкладка конфигуратора видна, все панели Eclipse свёрнуты в значки по краям окна; при переходе на другой редактор или закрытии конфигуратора они возвращаются.

Адреса: каждому блоку — окно 16 МБайт (маска `0xFF00_0000`). «Авто» — первый блок типа занимает окно типа (GPIO `0x1100_0000`, TM1638 `0x1200_0000`, STIM `0x1300_0000`, UART `0x1400_0000`, SPIFLASH `0x1500_0000`, SIFU `0x1600_0000`), остальные — первое свободное с `0x1100_0000`. Заняты: IMEM `0x00`, CLINT `0x02`, PLIC `0x0C`, DMEM `0x10`, симулятор `0x1F`.

Формат `.gwsoc` версии 2 — список `"periph"` (тип, имя, адрес, настройки и выводы каждого блока). Файл версии 1 (фиксированные `"blocks"` с `enabled`) конфигуратор и генератор читают и переводят сами: включённые блоки становятся блоками с именами типов.

## Командная строка

```
py sw/socgen/socgen.py fw/boards/tangnano9k/tangnano9k.gwsoc            # проверить и сгенерировать top.sv, riscv.cst, soc.h
py sw/socgen/socgen.py fw/boards/tangprimer20k/tangprimer20k.gwsoc --check    # только проверить (Tang Primer 20K)
py sw/socgen/socgen.py fw/boards/tangnano9k/tangnano9k.gwsoc --build    # + сборка маршрутом из .gwsoc (по умолчанию Gowin EDA)
py sw/socgen/socgen.py fw/boards/tangnano9k/tangnano9k.gwsoc --build --toolchain apicula   # или явно: gowin / apicula
```

Проверка без Eclipse: `py -m http.server 8765 --directory .` из корня репозитория, затем в браузере
`http://localhost:8765/sw/socgen/web/index.html?cfg=../../../fw/boards/tangprimer20k/tangprimer20k.gwsoc` (сохранение и сборка — только в Eclipse).

**apicula и Tang Primer 20K (GW2A-18).** Открытый маршрут собирает проект 20K и с отладчиком (у GW2A-18 apicula
знает примитив GW_JTAG; генератор дописывает выводы JTAG в копию `.cst` только для nextpnr - `impl_oss/riscv_oss.cst`),
Fmax ~61 МГц. Но на плате память BSRAM такой сборки не работает: IMEM читается нулями, ядро стоит на адресе 0
(проверено 2026-10-02, OSS CAD Suite: Yosys 0.69, apicula 0.34). Программу на 20K собирайте в Gowin EDA.

## Маршрут Gowin EDA

Собирается проект `hw/boards/<плата>/riscv.gprj` командной строкой IDE `gw_sh.exe` (`open_project` + `run all`): те же настройки
`hw/boards/<плата>/impl/riscv_process_config.json`, `riscv.sdc`, отладчик JTAG. Результат — `hw/boards/<плата>/impl/pnr/riscv.fs`, отчёты — в `hw/boards/<плата>/impl/pnr`,
журнал — `hw/boards/<плата>/impl/socgen_gw_sh.log`. `gw_sh.exe` ищется так: ключ `--gowin`, переменная `GOWIN_HOME`
(каталог IDE или установки), затем `C:/Program Files/Gowin/*`, `C:/Gowin/*`. Генератор проверяет, что период `clk_core` в
`riscv.sdc` соответствует частоте rPLL, и предупреждает, если нет.

**Выводы двойного назначения.** Флеш платы сидит на выводах MSPI (Tang Nano 9K — 59–62, Tang Primer 20K — L10, M9, R10, P10). Если блоки занимают такие выводы, генератор ставит в `hw/boards/<плата>/impl/riscv_process_config.json` флажок «Use MSPI as regular IO» (`"MSPI": true`, иначе `false`), а открытому маршруту передаёт `gowin_pack --mspi_as_gpio`. У GW2A-18 так же обрабатываются SSPI (кнопка сброса Tang Primer 20K на T10 — вывод SI), READY и DONE (светодиоды LED1, LED0 на A13, C13) и RECONFIG_N. Таблица функций — `dualPurpose` кристалла в `web/devices.js` (`mkdevices.py`).

**SPIFLASH.** Блок с загрузкой подключается к порту `boot_*` процессора (загрузчик один — у второго блока загрузка выключается); без такого блока `top.sv` подаёт на порт нули. В `soc.h` — объём флеш, частота SCK, область образа и свободная область (`SPIFLASH_USER_ADDR`). При добавлении блок сам занимает выводы флеш Tang Nano 9K (59–62), если они свободны. Настройка «Конфигурация и программа» выбирает способ хранения: «в SRAM или встроенной flash» (`"fpgaConfig": false`, загрузчик выключен, `BOOT_EN = 0`, программа в битовом потоке) или «в этой флеш, загрузка по MSPI» (`"fpgaConfig": true`: загрузчик включён, битовый поток с адреса 0, образ программы не ниже `0x80000`, по умолчанию `0x100000`; в `soc.h` — `SPIFLASH_FPGA_CONFIG`; записывает `fpgaload.py spiflash`). Старый ключ `"boot"` больше не используется.

Нужна установленная **Gowin EDA Education** (бесплатная, без лицензии) — [sdk/SETUP.md, п. 4](../../sdk/SETUP.md#4-gowin-eda).

## Открытый маршрут: ограничения (OSS CAD Suite 2026-09-29, apicula 0.34)

- **Отладчик.** apicula не умеет примитив `GW_JTAG` для GW1N-9C (есть только для GW2A-18C). Сборка идёт с `DEBUG_EN = 0` и макросом `GWSOC_NO_JTAG_PINS`: порты JTAG убираются из `top.sv`, выводы 5–8 остаются за JTAG ПЛИС.
- **Частота.** nextpnr для конфигурации по умолчанию даёт около 32 МГц против 45 МГц у Gowin EDA: другой синтез, нет многотактных путей из `riscv.sdc`. Битовый поток собирается (`--timing-allow-fail`), а генератор пишет предупреждение с частотой rPLL, которую маршрут выдерживает.
- **ABC9.** Этап `map_luts` штатного `synth_gowin` в Windows-сборке Yosys падает на assert в `write_xaiger2`. Поэтому LUT отображает классический `abc -lut 4:8`.
- **`syn_ramstyle`.** Значение `"distributed_ram"` понимает только GowinSynthesis; для Yosys атрибут снимается.

Маршрут Gowin EDA использует те же `top.sv`, `cpu.sv` и `riscv.cst` и остаётся основным: отладчик, `riscv.sdc`, 45 МГц.

## Новый блок периферии

1. Модуль — в `hw/src/periph/<тип>/` по правилам [periph/README.md](../../hw/src/periph/README.md) (модуль, тест и README.md — его показывает библиотека конфигуратора), файл — в `hw/boards/<плата>/riscv.gprj`.
2. `socgen.py`: запись в `TYPES` (название, окно адреса, группа `iface`/`gpio`/`custom`, есть ли прерывание, модуль), сигналы выводов в `inst_signals`, проверки настроек в `validate`, экземпляр в `gen_top`, настройки в `gen_soc_h`.
3. `web/app.js`: та же запись в `TYPES` (с описанием `about` и значениями по умолчанию `defaults`), `instSignals`, проверки, поля настроек в `instForm`/`wireInstForm`, строки «+» в `instRows` для необязательных выводов.
4. Плагин Eclipse берёт страницу из своей копии `web/`: после правок пересоберите его (`py sw/socgen/eclipse/build.py`) и переустановите.
