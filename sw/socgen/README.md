Конфигуратор ПЛИС askoRV32 (socgen)
====================================

Визуальная настройка проекта ПЛИС GW1NR-LV9QN88P из проекта прошивки в Eclipse — по образцу CubeMX у STM32.
Источник правды — файл [`fw/riscv.gwsoc`](../../fw/riscv.gwsoc) (JSON). По нему генерируются:

| Файл | Что в нём |
|------|-----------|
| `hw/src/top.sv` | верхний уровень: порты-выводы, параметры `cpu`, карта адресов и memmux пользовательской периферии на порту `per_*`, GPIO/TM1638/STIM/UART и подключение их прерываний. **Не редактировать вручную** |
| `hw/src/riscv.cst` | назначение выводов `IO_LOC` / `IO_PORT` и их стандарты I/O |
| `fw/Core/Inc/soc.h` | описание ПЛИС для прошивки: `SYSCLK_HZ`, ядро и память, `XXX_PRESENT`/`XXX_BASE` устройств, настройки UART, `PLIC_SRC_Type` и имена обработчиков прерываний (cp1251, CRLF — как файлы прошивки). Путь — `paths.soc` в `.gwsoc`, по умолчанию `Core/Inc/soc.h` |
| `hw/impl/pnr/riscv.fs` | битовый поток Gowin EDA (маршрут по умолчанию), при сборке |
| `hw/impl_oss/riscv.fs` | битовый поток открытого маршрута (Yosys + nextpnr-himbaechel + apicula), при сборке |

Процессор — такт (rPLL), сброс, ядро, отладчик JTAG, IMEM и DMEM, CLINT, PLIC и системная шина — в [`hw/src/cpu.sv`](../../hw/src/cpu.sv); его правят вручную. Имена сигналов, экземпляров и параметров `top.sv` зарезервированы: цепь с таким именем конфигуратор не примет.

## Состав

| Путь | Назначение |
|------|------------|
| `web/` | страница конфигуратора: изображение микросхемы, блоки, диалоги (`index.html`, `app.js`, `style.css`) |
| `web/device.js` | 88 выводов корпуса QFN88P с банками и функциями (из Gowin IDE `data/device/GW1NR-9C/QFN88P.json`) |
| `socgen.py` | генератор и сборка открытым маршрутом |
| `eclipse/` | плагин Eclipse: редактор `.gwsoc` (страница `web/` во встроенном Edge), команда «Конфигуратор ПЛИС», `build.py` |

Правила — выбор адресов, расчёт rPLL, номера прерываний, делитель UART, стандарты выводов, проверки — записаны и в `web/app.js`, и в `socgen.py`. Меняя их, правьте оба файла.

## Работа в Eclipse

Установка плагина — [sdk/SETUP.md, п. 11](../../sdk/SETUP.md#11-плагин-конфигуратор-плис-для-eclipse). Файл `riscv.gwsoc` открывается двойным щелчком в Project Explorer, либо командой **Конфигуратор ПЛИС** в меню проекта.

- **Блоки внутри микросхемы.** Переключатель в углу включает и выключает GPIO, TM1638, STIM, UART (выключенный блок полупрозрачный). Двойной щелчок по включённому блоку открывает его настройки: выводы, имена цепей, адрес регистров, разрядность, прерывание.
- **UART.** Выводы TX и RX (на Tang Nano 9K к UART программатора BL702 — 17 и 18), скорость, чётность, стоп-биты и глубина FIFO. Это значения после сброса: прошивка может сменить их регистрами. Диалог сразу считает делитель от частоты шины и фактическую скорость; ошибка больше 1 % — предупреждение, больше 2 % — ошибка.
- **Прерывания.** У STIM и UART — поле «Прерывание»: **PLIC** (по умолчанию; источники нумеруются 1, 2… в порядке блоков GPIO, TM1638, STIM, UART среди включённых), **локальная линия LI*n*** (номера 0, 1… в том же порядке) или «не подключено». Итог виден на блоках и на плитке PLIC, а в прошивку попадает через `soc.h`: `PLIC_SRC_UART`, `#define PLIC_UART_IRQHandler PLIC_SRC2_IRQHandler` или `UART_IRQn`/`UART_IRQHandler` для локальной линии. Если источников PLIC не хватает — ошибка с предложением увеличить их число в настройках ядра.
- **«Ядро askoRV32».** Тип ядра (конвейер или однотактное), расширение M и бит частного за такт, IMEM и DMEM (BSRAM 8/16/32 кБайт или синтезированная память в словах), отладчик JTAG, число источников PLIC (1…31). Диалог показывает частоту шины периферии (у однотактного ядра с BSRAM — треть rPLL) и сколько блоков BSRAM занято из 26 (вместе со шрифтом TM1638). Без расширения M конфигуратор напомнит сменить `-march` в Eclipse.
- **«Такт и сброс».** Частота кварца и его вывод (★ — выводы GCLK и входы PLL), rPLL: подбор делителей по нужной частоте или вручную с проверкой PFD, VCO и CLKOUT; вывод сброса.
- **Выводы.** Номера — внутри корпуса, имена цепей — снаружи. Цвет ячейки — банк, цвет кружка — блок, которому вывод назначен. Двойной щелчок по выводу — сигнал и стандарт I/O; по имени цепи — переименование на месте. Имена вида `led[3]` собираются в шину `led[5:0]`.
- **Таблица «Назначения выводов»** (как I/O Constraints во FloorPlanner) — IO_TYPE, DRIVE, PULL_MODE, BANK_VCCIO по каждому выводу; «*» — значение по умолчанию.
- **«Стандарты I/O…»** — общие значения и значения по банкам (`"banks"` в `.gwsoc`). Порядок: свои настройки вывода → банк → общие. Напряжение банка задаёт плата: на Tang Nano 9K банки 1–2 — 3,3 В (LVCMOS33), банк 3 — 1,8 В (LVCMOS18). Разные BANK_VCCIO у выводов одного банка — ошибка (Gowin EDA остановит размещение).
- **Панели.** Пока вкладка конфигуратора видна, все панели Eclipse (Project Explorer, Outline, Problems, Console...) свёрнуты в значки по краям окна; при переходе на другой редактор или закрытии конфигуратора они возвращаются. Панели, свёрнутые заранее, не трогаются.
- **«Собрать»** — сохранить файл, сгенерировать `top.sv` и `riscv.cst` и собрать битовый поток маршрутом из списка рядом с кнопкой: **Gowin EDA** (по умолчанию) или **apicula**. Выбор хранится в `.gwsoc` (`"build": { "toolchain": ... }`). Ход сборки — в консоли «askoRV32 - сборка ПЛИС».

Адреса: каждому блоку — окно 16 МБайт (маска `0xFF00_0000`). «Авто» — свой слот блока (GPIO `0x1100_0000`, TM1638 `0x1200_0000`, STIM `0x1300_0000`, UART `0x1400_0000`), а если он занят — первый свободный с `0x1100_0000`. Заняты: IMEM `0x00`, CLINT `0x02`, PLIC `0x0C`, DMEM `0x10`, симулятор `0x1F`.

## Командная строка

```
py sw/socgen/socgen.py fw/riscv.gwsoc            # проверить и сгенерировать top.sv, riscv.cst, soc.h
py sw/socgen/socgen.py fw/riscv.gwsoc --check    # только проверить
py sw/socgen/socgen.py fw/riscv.gwsoc --build    # + сборка маршрутом из .gwsoc (по умолчанию Gowin EDA)
py sw/socgen/socgen.py fw/riscv.gwsoc --build --toolchain apicula   # или явно: gowin / apicula
```

Проверка без Eclipse: `py -m http.server 8765 --directory .` из корня репозитория, затем в браузере
`http://localhost:8765/sw/socgen/web/index.html?cfg=/fw/riscv.gwsoc` (сохранение и сборка — только в Eclipse).

## Маршрут Gowin EDA

Собирается проект `hw/riscv.gprj` командной строкой IDE `gw_sh.exe` (`open_project` + `run all`): те же настройки
`hw/impl/riscv_process_config.json`, `riscv.sdc`, отладчик JTAG. Результат — `hw/impl/pnr/riscv.fs`, отчёты — в `hw/impl/pnr`,
журнал — `hw/impl/socgen_gw_sh.log`. `gw_sh.exe` ищется так: ключ `--gowin`, переменная `GOWIN_HOME`
(каталог IDE или установки), затем `C:/Program Files/Gowin/*`, `C:/Gowin/*`. Генератор проверяет, что период `clk_core` в
`riscv.sdc` соответствует частоте rPLL, и предупреждает, если нет.

Нужна установленная **Gowin EDA Education** (бесплатная, без лицензии) — [sdk/SETUP.md, п. 4](../../sdk/SETUP.md#4-gowin-eda).
Для одной только сборки полная установка (1,5 ГБ) не обязательна — достаточно части её файлов (около 310 МБ), см. там же.

## Открытый маршрут: ограничения (OSS CAD Suite 2026-09-29, apicula 0.34)

- **Отладчик.** apicula не умеет примитив `GW_JTAG` для GW1N-9C (есть только для GW2A-18C). Сборка идёт с `DEBUG_EN = 0` и макросом `GWSOC_NO_JTAG_PINS`: порты JTAG убираются из `top.sv`, выводы 5–8 остаются за JTAG ПЛИС.
- **Частота.** nextpnr для конфигурации по умолчанию даёт около 32 МГц против 45 МГц у Gowin EDA: другой синтез, нет многотактных путей из `riscv.sdc`. Битовый поток собирается (`--timing-allow-fail`), а генератор пишет предупреждение с частотой rPLL, которую маршрут выдерживает.
- **ABC9.** Этап `map_luts` штатного `synth_gowin` в Windows-сборке Yosys падает на assert в `write_xaiger2`. Поэтому LUT отображает классический `abc -lut 4:8`.
- **`syn_ramstyle`.** Значение `"distributed_ram"` понимает только GowinSynthesis; для Yosys атрибут снимается.

Маршрут Gowin EDA использует те же `top.sv`, `cpu.sv` и `riscv.cst` и остаётся основным: отладчик, `riscv.sdc`, 45 МГц.

## Новый блок периферии

1. Модуль — в `hw/src/periph/<устройство>/` по правилам [periph/README.md](../../hw/src/periph/README.md), файл — в `hw/riscv.gprj`.
2. `socgen.py`: запись в `BLOCKS` (слот адреса, `irq="irq_<имя>"`, если есть прерывание), значения по умолчанию, сигналы выводов, проверки, экземпляр в `gen_top`, строки в `gen_soc_h`.
3. `web/app.js`: те же `BLOCKS`, `normalize`, `signals`, проверки, плитка в `tileDefs`, диалог в `blockDialog`, цвет `--c-<имя>` в `style.css`.
4. Плагин Eclipse берёт страницу из своей копии `web/`: после правок пересоберите его (`py sw/socgen/eclipse/build.py`) и переустановите.
