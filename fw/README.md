#### Прерывания
Описание аппаратной части: [hw/info/interrupts.md](../hw/info/interrupts.md).

- **Сборка:** `-march=rv32i_zicsr`. В Eclipse: *C/C++ Build → Settings → Target Processor → Other extensions* = `_zicsr`, уже задано в `.cproject`.
- **Стартовый код** `start.S`:
  - `mtvec` = `__vector_table | 1` (векторный режим);
  - таблица из 32 переходов, выравнивание 128 байт: вход 0 — исключения, вход N — прерывание с кодом N;
  - все обработчики — слабые ссылки. `Default_Handler` и `Default_Exception_Handler` останавливают программу в бесконечном цикле, причину можно посмотреть в `mcause`, адрес — в `mepc`.
- **Свой обработчик** — функция с именем из таблицы векторов и атрибутом `__IRQ` (`core_riscv.h`). Компилятор сам сохраняет регистры и выходит по `mret`. **Флаг источника нужно сбросить в обработчике**, иначе прерывание сразу повторится.

| Обработчик | Код | Источник |
|------------|:---:|----------|
| `Exception_Handler` | — | все исключения (`mcause` < 0x80000000) |
| `MSI_IRQHandler` | 3 | программное прерывание CLINT |
| `MTI_IRQHandler` | 7 | машинный таймер CLINT |
| `MEI_IRQHandler` | 11 | PLIC: диспетчер в `plic.c` вызывает обработчики источников |
| `STIM_IRQHandler` | 16 | таймер STIM (LI0) |
| `LI1_IRQHandler`…`LI15_IRQHandler` | 17…31 | свободны |

- **Функции** (`core_riscv.h`, `clint.h`, `tim.h`, `plic.h`):
  - `__enable_irq()`/`__disable_irq()` — `mstatus.MIE`;
  - `IRQ_Enable(IRQn)`/`IRQ_Disable(IRQn)` — `mie`;
  - `CLINT_SetTimeout(ticks)`/`CLINT_SetCompare(time)`/`CLINT_GetTime()`;
  - `STIM_IT_STATE()`/`STIM_CLEAR_FLAG_UPDATE()`;
  - `CORE_GetCycles()` — `mcycle`;
  - `PLIC_SetPriority(src, 1..7)`/`PLIC_Enable(src)`/`PLIC_SetThreshold()`, `PLIC_Claim()`/`PLIC_Complete()`.
- **PLIC** (`plic.h`, `plic.c`) собирает прерывания периферии в одно прерывание MEI. `MEI_IRQHandler` в цикле делает `claim`, вызывает обработчик источника и `complete`. Обработчики источников — обычные функции **без** `__IRQ`:

  | Обработчик | Источник | Периферия |
  |------------|:--------:|-----------|
  | `PLIC_STIM_IRQHandler` | 1 | таймер STIM (он же LI0 — разрешать один из путей) |
  | `PLIC_SRC2_IRQHandler`…`PLIC_SRC8_IRQHandler` | 2…8 | свободны (UART, SPI…), номера — `PLIC_SRC_Type` в `periphery.h` |

  Необъявленный обработчик — слабая ссылка на `PLIC_Default_Handler`, который запрещает источник, чтобы запрос по уровню не вызывал прерывание бесконечно. Флаг в периферии нужно сбрасывать в обработчике источника.
- **Частота** `SYSCLK_HZ` в `periphery.h` — такт периферии, от него считают STIM и `mtime`: 13.5 МГц для конвейерного ядра, 4.5 МГц для однотактного. При смене `CORE_TYPE` в `top.sv` её нужно поменять.

#### Примеры (`main.c`, макрос `EXAMPLE`)
| `EXAMPLE` | Что делает |
|:---:|------------|
| 0 | прежний пример: счётчик таймера STIM на индикаторе TM1638, без прерываний |
| 1 | LED0 мигает раз в секунду по прерыванию таймера STIM: предделитель до 1 кГц, событие каждые 500 мс |
| 2 | LED0 мигает раз в секунду по прерыванию машинного таймера: обработчик сдвигает `mtimecmp` на 0.5 с от прошлого порога, без накопления ошибки |
| 3 | то же, что 1, но через PLIC: источник 1, MEI, обработчик `PLIC_STIM_IRQHandler`. Образец подключения любой периферии к PLIC |

По умолчанию `EXAMPLE = 1`. Другой пример выбирается в начале `main.c` или флагом `-DEXAMPLE=2` в настройках проекта.

#### Отладка
Через JTAG платы в Eclipse (OpenOCD + GDB): готовая конфигурация `riscv Debug OpenOCD.launch`, конфиг OpenOCD — `openocd/askorv32_tangnano9k.cfg`. Установка — [sdk/SETUP.md](../sdk/SETUP.md), раздел 8, устройство отладчика — [hw/info/debug.md](../hw/info/debug.md). Программа загружается отладчиком в BSRAM, пересобирать ПЛИС не нужно.

#### Замечания
1. Добавлен глобальный указатель gp для организации более быстрого относительного смещения в секции глобальных данных. Если адреса находятся в области +-2048 байт (+-2кБайт), то к ним осуществляется более быстрый доступ относительно глобального указателя gp, который выставлен со смещением 2048 байт от начала сегмента глобальных данных. Но в реальности, почему-то, работает смещение на 2032 байта, не совсем понимаю почему не дотягивает до 2ух кБайт.
